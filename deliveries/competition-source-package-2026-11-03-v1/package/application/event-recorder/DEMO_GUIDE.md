# 演示素材与操作口径

优先录真实软件串口窗口、板上LED和手指按键同框，不用说明页或PPT录屏充当运行。此文件是后续拍摄指导，不代表视频已拍好，也不恢复B开发派工。

设备配置和串口接收必须先由主线确认就绪。按KEY0是应用复位，不能误按RESET/PROG；不要为了拍摄带电插拔JTAG或切跳线。不把配置状态异常的片段剪成成功。

可以用三段展示：

1. 正常动作：复位后依次累计保持KEY1、KEY2、KEY3，最后全松；每步短于等待超时并足够两次采样。拍到LED6采集、正常最终图样及同轮REC2四条E/END。
2. 错误顺序：KEY2先按松，再KEY1按松；拍到报警灯及fault1和2→0→1上下文冻结。说明“模拟设备先后顺序错误”，不要说真实工业设备已接入。
3. 等待超时：KEY1保持超过2秒后松开，再按松KEY1；拍到fault2、state1接受与超时index差20、后续上下文及完整END。以实际报告为准，本包最终状态表若尚未通过此项则不得提前采用成功文案。

建议每段保留原始拍摄文件和原始UART，同一轮次对应，剪辑可加少量字段解释字幕；不能拿历史CoreMark/ILA画面冒充应用实时波形。不要录桌面全屏敏感资料、账号、许可证或下载器序列号。电脑已有录屏素材仍保持其原版本身份，此包没有新拍摄的视频、应用ILA或真实传感器照片。

“这是一套由自研RISC-V CPU运行裸机C程序的低速事件记录原型。按键模拟设备状态，程序用同一采样口径检查动作顺序与等待超时，环形保存故障上下文，结束后输出可核对的时间账本。它的目标是帮助回答哪里先出错、故障前后发生了什么，而不是只点亮报警灯。现阶段是有限批次采集，不是高速逻辑分析仪或已认证工业产品。”
