# 可编程事件记录与故障回溯原型：M1软件阶段

2026-11-03。入口：`RESULTS.json`、`COMPARISON.json`、`FROZEN_PLAN_v2.json`；说明见项目报告 `reports/application/2026-11-03-event-recorder-and-independent-advanced.md`。

## 已真实打通

GCC编译RV32I/ILP32 C → 原SM2 CPU/SoC RTL → 同步仿真存储 → 实际GPIO同步器/MMIO读取 → 实际RTL计时器读取 → C过滤/顺序/超时检测及环形记录 → CPU驱动原UART TX → TB独立解码TX引脚，与每笔接受字符及冻结期望核对。采集期间不打印，结束后导出。7场景×2模式×每次2轮复位；当前结果14组均通过。

这是RTL仿真，不是板上程序或工业部署。未启动PDS、服务器、GUI、JTAG或操作电源。公共CPU/SoC、外设与已验D300快照保持原字节。本地合格恢复快照沿用 `deliveries/accepted-basic-sm2-2026-11-02-v1`，完整清单已回核，不重复拷贝大目录。

## 精确规则

- 3位状态，合法循环0→1→3→7→0；初态0。GPIO同步后软件轮询，每12000目标tick采样，32次为一批。
- 连续2个同值样本才接受变化；单样本或交替抖动拒绝。状态1保持6个后续采样无变化触发超时。reason1顺序错误、reason2超时。
- 8槽环形上下文，每条4×32bit：软件观察tick、样本索引、状态、原因。故障前满缓冲时覆盖最旧项并显式evicted计数；故障后收2个变化事件即冻结，后来的变化显式rejected计数。故障后无新变化时在32样本批次结束导出，不能声称总能收足2条。
- 最终满窗口为5条故障前+故障条+2条故障后；`wrap_fault_window`精确核对13条插入后的最后8条、evicted5、frozen1。
- 仿真设置每目标tick10ns仅为加速时基，不是27MHz板上采样实测。在27MHz标称下12000tick约0.444ms，32样本仅约14.22ms，不适合直接让人按键演示；板级慢速参数/启动方式需下一阶段单独冻结，不自动构建或下载。
- 单样本可能漏掉短于一个采样间隔的脉冲；两样本滤波还会主动拒绝未连续观察到2次的变化。保守候选时序预算≤25004tick，当前测得变化到记录最大18024.5tick，仅覆盖本批相位；不是所有相位/最短脉冲的穷尽证明。
- timestamp表示软件观察时间，实际与timer MMIO读值和波形时基关联；不冒称真实输入边沿精确时刻。低32位时间戳，当前不跨回绕；无中断、无RX命令、无外部传感器、高速分析仪或持续无限监测。

## 量化对照

两模式同32样本过程、同检测器、同故障上下文。dense额外保存/导出32组tick+state原始采样；event仅保留上下文。共同的64word `samples` 是审核仪器化，不计产品记录存储；当前C为便于审计两模式均保留了它，**不能声称链接后整个RAM已经节省66.67%**。

记录有效载荷容量：raw+同等context=256+128=384B，对event128B，减少66.67%；不是“完整原始波形无损压缩”。回绕丢弃老上下文明确计数。正常UART字符1216→256，少78.95%；各场景约69.97%–90.57%，详COMPARISON。仿真文件Windows文本输出会将LF转CRLF，按C实际发送字符计有效UART字节，保留原文件。

处理段tick不含串口/等待，正常3002→2722；这是带共同审计的当前代码局部处理成本，不是整CPU占用降低。两者均忙轮询，整个观察窗几乎相同，不宣称全程CPU性能改善。
